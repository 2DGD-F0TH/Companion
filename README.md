## What this is

This repository is a collection of hackable examples and programs that are meant to be:

- **Compilable** - real, working code, not fragments;
- **Executable** - clone it, run it, see it on screen;
- **Self-contained** - each listing stands alone, with minimal dependencies;
- **Explained** - the code is heavily commented, allowing you to understand what's happening;
- **Hackable** - the code is structured in a way that allows you to quickly edit variable values and see how things change.

The book walks through concepts, this repo gives you **runnable programs** - small, focused listings you can execute, break, fix, and build on.

## What this isn't

- **Not a framework.** Nothing here is designed to be dropped wholesale into a production game as a dependency. Take the ideas, take the code, adapt it.
- **Not a replacement for the book.** The examples assume you've read (or are reading) the corresponding chapters.
- **Not finished.** Like the book itself, this is a living repository. Examples get added, revised, and occasionally retired.

## Getting started

```bash
git clone https://github.com/2DGD_F0TH/Companion.git
cd Companion
```

Each subfolder will have its own README file explaining how to run each example.

### Why this license and not MIT or Apache?

MIT, Apache-2.0, and the Unlicense are the most common licenses, and I've used them for plenty of things. But I'm starting to have second thoughts about them, considering the current climate in the world of software development. Plus they all permit a specific behaviour I want to avoid here: **anyone can fork this repository, make no meaningful changes (or any at all), and sell access to it.**

That's not a hypothetical. Free educational repositories regularly get scraped and resold as courses, bundles, and "complete guides." When that happens, learners end up paying for something that was given away freely, and the original project gets nothing - not credit, not contributions, not the reputation benefit that sustains it.

PolyForm Noncommercial seems to strike a good balance:

| Activity                                    | Allowed? |
| ---                                         | ---      |
| Using this code in a game you sell          | Yes      |
| Using this code in a game you give away     | Yes      |
| Modifying and redistributing it for free    | Yes      |
| Teaching a class that uses it               | Yes      |
| Selling access to this repo or a copy of it | No       |

The restriction targets **reselling the resource**, not **using the resource**. If you're here to make games, nothing changes for you.

If you have a use case that the license seems to block but which you believe is in the spirit of the project - teaching a paid workshop, bundling examples into a commercial course, translating the material - **open an issue and ask.** I'm happy to grant permission on a case-by-case basis. The license sets a default; it doesn't have to be the last word.
